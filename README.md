# Wolsar Worship — помощник служения

Система расписаний для церкви: личная карточка, команда, календарь и помощник администратора.

## Структура

- `backend/` — FastAPI, бизнес-правила, PostgreSQL, миграции и тесты.
- `frontend/` — React, TypeScript, SCSS и Ant Design.
- `bot_service/` — отдельный Telegram-сервис; общается с backend по HTTP, без доступа к БД.
- `.github/workflows/` — CI, публикация Docker-образов в GHCR и ручной деплой.
- Корневая `.env` — общая локальная конфигурация; в Git не попадает.

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните пароли, `BOT_SERVICE_TOKEN`, `JWT_SECRET` и токены ботов.
Для обычного запуска тестовая БД не нужна. Настройки проверок вынесены в `.env.test` и `compose.test.yaml`. `DATABASE_URL` необязателен:
backend собирает URL из `DATABASE_USERNAME`, `DATABASE_PASSWORD`, `DATABASE_HOST`, `DATABASE_PORT`,
`DATABASE_NAME`, корректно кодируя спецсимволы. Явный `DATABASE_URL` имеет приоритет для CI/внешней БД.
В Compose URL формируется из отдельных переменных; пароль не записан в YAML.

Не публикуйте `.env`. Ключ OpenAI, ранее опубликованный в чате, следует отозвать и заменить.
Ни один ключ или токен не передаётся в сборку frontend. Не используйте `docker compose config`
для публикации конфигурации: эта команда раскрывает подставленные значения; для проверки есть `--quiet`.

Если база уже создана в Docker volume, изменение `.env` не меняет пароль существующего пользователя.
Смените его в PostgreSQL отдельно; не удаляйте volume с нужными данными.

## Запуск

Из корня (Docker Desktop должен работать):

```powershell
docker compose up --build -d
# http://localhost:8080 — веб, http://localhost:8000/docs — API
# WEB_URL в .env для этого режима: http://localhost:8080
```

Для разработки в отдельных терминалах:

```powershell
cd backend
poetry install --with dev
poetry run alembic upgrade head
poetry run uvicorn worship_bot.main:app --reload
```

```powershell
cd frontend
npm ci
npm run dev
# http://localhost:5173, API проксируется на localhost:8000
```

Бота локально запускайте из корня после `pip install -r bot_service/requirements.txt`:
`python -m bot_service.main`. `BACKEND_URL` по умолчанию — `http://localhost:8000/api/v1`.
Не запускайте одновременно два polling-процесса с одним Telegram-токеном.

Пример интерфейса без БД: `http://localhost:5173/?demo=1`. Данные помечены как демонстрационные,
изменения остаются в памяти браузера; обращения к модели в этом режиме отключены.

## Вход и роли

Регистрация на сайте создаёт личный аккаунт с логином и паролем, без автоматического вступления в церковь или команду. Откройте «Церкви и команды», выберите служение и отправьте заявку. Администратор служения проверяет заявку, выбирает роли и принимает либо отклоняет её. Одобрение даёт права участника; администраторы назначаются отдельно.

Существующие аккаунты и назначения сохраняются. Если вы ещё вошли, задайте логин и пароль в «Моя карточка». Если доступ потерян, локальный владелец установки может получить одноразовую ссылку для существующего пользователя (замените 1 на ID карточки):

```powershell
docker compose exec api python -m worship_bot.setup --login 1
```

После перехода по ссылке задайте собственные реквизиты в карточке. Для первой настройки пустой установки используйте `docker compose exec api python -m worship_bot.setup`: команда создаст первого администратора и откажется повторно создавать его в заполненной базе.

Telegram подключается из «Моя карточка → Привязать Telegram»: откройте выданную ссылку на @wolsar_worship_bot. Она одноразовая и действует 10 минут; привязка сохраняет тот же аккаунт. Бот поддерживает `/login`, `/profile`, `/schedule` и `/plan` для администратора. `/register` направляет на регистрацию сайта. Одноразовая ссылка входа действует пять минут; в БД хранится только хэш кода. После входа используется HttpOnly SameSite-cookie. Пароли хранятся как scrypt-хэши с индивидуальной солью; повторные неверные попытки временно блокируются.

Администратор может назначать других администраторов своего служения. Все актуальные сервисы, включая Telegram и доставку веб-уведомлений, запускаются общей командой Compose. VK-бот пока не реализован.

| Роль | Возможности |
| --- | --- |
| Участник | Своя карточка, календарь и список команды своего служения |
| Координатор | Дополнительно события, назначения и репетиции |
| Администратор | Дополнительно помощник и управление доступом участников |
| Разработчик | Администрирование служений и назначение администраторов |

Видимость кнопок определяется permissions от backend. Сервер независимо проверяет права.
Старые маршруты церквей, участников и календаря, не имеющие полной проверки контекста,
теперь требуют служебный токен бота. Веб использует `/api/v1/portal/*`.

## Помощник расписания

Выберите служение и месяц. Администратор может загрузить до четырёх файлов:
XLSX, CSV, TXT, PNG, JPG, WEBP, до 8 МБ каждый. XLSX читается локально: максимум 10 листов,
1000 строк и 50 колонок на лист; формулы не исполняются. Для фотографий используется vision.
При отправке сообщения извлечённые данные/фотографии и данные выбранного служения передаются OpenAI.
Не загружайте данные, на передачу которых у вас нет согласия.

Backend добавляет состав команды, календарь выбранного месяца и историю двух предыдущих месяцев.
Диалоги и черновики сохраняются в БД; вложения удаляются из записи после применения.
Модель возвращает структурированный черновик или уточняющий вопрос. Можно уточнять пожелания в диалоге.
Применение — отдельная кнопка: проверяются даты, роли, участники, версия черновика и уже занятые места.
События и назначения записываются одной транзакцией. Применённый черновик повторно не используется.
Модель не получает произвольного SQL или прямого доступа к БД.

`OPENAI_MODEL` выбирается в `.env`, стандартное значение — `gpt-6.1-sol`, с изображениями и Structured Outputs.
Доступность зависит от вашего OpenAI-проекта. Получить список моделей после замены ключа:

```powershell
# Если ключ задан в окружении PowerShell; без --data и Cookie:
curl.exe https://api.openai.com/v1/models -H "Authorization: Bearer $env:OPENAI_API_KEY"
```

Официальные источники: [модели](https://developers.openai.com/api/reference/resources/models/methods/list),
[GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Качество распознавания фотографий и справедливость распределения требуют проверки на реальных
расписаниях. Неопознанные имена модель должна отметить, не заменять похожими.

## Уведомления

Telegram-сервис доставляет очередь назначений, снятий, приглашений и напоминаний.
Задания выдаются с пятиминутной арендой и токеном подтверждения; ошибки повторяются с задержкой,
максимум пять попыток. Доставка как минимум однократная: при сбое после отправки возможен повтор.
Репетиции и время первого напоминания настраиваются через API событий; второе напоминание
добавляется за два часа до события/репетиции, если первое включено. Пользователь должен начать диалог с ботом.
VK-токен предусмотрен конфигурацией, но VK-адаптер пока не реализован.

## Проверки и CI/CD

Из `backend/`: `poetry run pytest -q`, `poetry run mypy`,
`poetry run ruff check --config pyproject.toml worship_bot tests migrations ../bot_service`.
Из `frontend/`: `npm test`, `npm run build`, `npm run format:check`.
Полный PostgreSQL-набор: из корня `docker compose --env-file .env --env-file .env.test -f compose.yaml -f compose.test.yaml --profile test run --build --rm test-runner`.

CI проверяет backend и frontend, применяет миграции на отдельной PostgreSQL и запускает тесты.
После успешного push в `main` публикуются `backend`, `frontend`, `bot` в GHCR
с тегами `main` и SHA коммита. Реальные секреты CI не нужны; реквизиты его одноразовой базы фиктивные.

Подготовка к публикации и описание проверок: [GITHUB_SETUP.md](GITHUB_SETUP.md).

### Оформление интерфейса

Кнопка выбора темы находится в верхней панели и на странице входа. Доступны светлая,
тёмная, мятная, индиго и сливовая темы. Выбор сохраняется в браузере; при первом входе
используется системная светлая/тёмная тема. Палитры заданы в `frontend/src/themes.ts`,
общие поверхности используют CSS-переменные, компоненты Ant Design — те же токены.

Stolzl и IF Kica подключены локально из предоставленных файлов в `frontend/public/fonts/`;
загрузка из Google Fonts не требуется. Материалы команды находятся в `frontend/public/brand/`.
Карточка служителя доступна отдельной страницей `/profile`.

## Первый запуск в Docker без бота

```powershell
docker compose up --build -d
docker compose exec api python -m worship_bot.setup
```

Команда настройки попросит имя, фамилию, название церкви и служения, создаст первого
администратора и базовые роли, затем выдаст ссылку входа на пять минут. Повторное создание
первого администратора блокируется, если в БД уже есть пользователи. Чтобы снова войти:
`docker compose exec api python -m worship_bot.setup --login 1` (укажите ID своего пользователя).
Команда доступна только владельцу Docker/сервера; публичного выдающего ссылки маршрута нет.

Откройте `http://localhost:8080`. В «Участники» администратор может добавлять карточки
служителей с ролями и менять уровень доступа на «Администратор». Последнего администратора
нельзя понизить, пока не назначен другой. Созданные таким способом карточки подходят для
проверки расписания; Telegram-аккаунт автоматически к ним не привязывается.

Основная БД хранится в Docker volume. `docker compose down` останавливает приложение,
не удаляя данные. Не добавляйте `-v`, если хотите сохранить созданных людей и события.
В локальной `.env` порт БД — 5434, чтобы не конфликтовать с установленным PostgreSQL.
`test:` внутри healthcheck — проверка готовности контейнера, а не тестовая база.

## Уведомления на сайте

В личной карточке есть «Включить уведомления», отключение для этого устройства и проверка
доставки. Браузер запрашивает разрешение только после нажатия кнопки. Service worker получает
Web Push, включая закрытую вкладку; отдельный `push-worker` доставляет уведомления из очереди
с повторными попытками, удалённые подписки отключаются. Telegram и Web Push доставляются независимо.

`VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY` и `VAPID_SUBJECT` задаются в `.env`. Приватный ключ
не передаётся браузеру. Локальная пара уже создана; сохраняйте её между перезапусками.
Для нового окружения пару можно создать через `py_vapid` или стандартный P-256 генератор.
Укажите в `VAPID_SUBJECT` контакт владельца сервера в формате `mailto:...`.

Для телефона нужен HTTPS; обычный HTTP по адресу компьютера в локальной сети для push не подходит.
Для проверки на самом компьютере подходит localhost. На iPhone сайт нужно добавить на домашний
экран и запускать оттуда. Наличие подписки и последнее разрешение браузера видны в списке участников:
«Подключены», «Нужно включить», «Нужно проверить» (нет проверки 30 дней).
Сайт не видит блокировку в настройках ОС, режим «Не беспокоить» и факт прочтения уведомления.
Статус «Подключены» означает наличие активной подписки хотя бы на одном устройстве.

Тесты запускаются отдельно: скопируйте `.env.test.example` в `.env.test`, задайте отдельный пароль,
затем используйте команду из раздела проверок. Тестовые данные автоматически в рабочую БД не загружаются.

## Шаблоны и создание событий

В «Событие» доступны два режима: «По шаблону» и «Своё событие». Базовые варианты:
воскресное собрание, воскресная молитва, общее лидерское собрание, вечер хвалы и молитвы.
Администратор может создать собственный шаблон или копию базового и настроить название,
заметки, роли и назначения. Репетиция в шаблоне задаётся интервалом в минутах до события;
календарная дата выбирается при создании. Собственные шаблоны сохраняются отдельно для
каждого служения. Их изменение не меняет ранее созданные события.

В каждом событии можно отдельно задать дату, время, репетицию, информацию для команды,
несколько мест одной роли, служителей и напоминания. Дата и время выбираются раздельно,
без подтверждения скрывающейся кнопкой «ОК». Описание отображается как обычный текст
с сохранением переносов строк, пустых строк и эмодзи.

Ссылка на Telegram-бота: https://t.me/wolsar_worship_bot. Бот запускается вместе с API, веб-интерфейсом и обработчиком уведомлений:
`docker compose up --build -d`. Для первого знакомства — `/start`, регистрация — `/register`,
одноразовая ссылка входа — `/login`.

## Обычный вход по логину и паролю

Первый существующий аккаунт без Telegram можно открыть одноразовой ссылкой из команды:
`docker compose exec api python -m worship_bot.setup --login 1` (замените 1 номером своей карточки).
После входа откройте «Моя карточка → Вход в аккаунт», задайте логин и пароль. Повторная
регистрация не нужна: сохраняются тот же пользователь, служение и права администратора.
Дальше на странице входа используйте вкладку «Логин и пароль» независимо от Telegram.
При смене логина или пароля потребуется текущий пароль. Пароль хранится как scrypt-хэш
со случайной солью; после пяти неверных попыток вход блокируется на пять минут.

Обычный `docker compose up --build` запускает PostgreSQL, API, frontend, push-worker и
Telegram-бота. Отдельного профиля для бота нет; заполненный TELEGRAM_BOT_TOKEN обязателен.
VK-клиент пока не реализован; наличие VK_BOT_TOKEN не означает, что бот работает во ВКонтакте.


### Роли и Telegram-кнопки

Справочник прославления включает ведущий и бэк-вокал, акустическую и электрогитару,
бас, барабаны, клавиши, скрипку, звук и танцы. Миграция дополняет существующие команды,
сохраняя их роли и назначения. В «Участники → Роли команды» администратор может
добавить собственную роль в справочник; она становится доступна и в заявках.

В Telegram отправьте `/start`, чтобы получить кнопки расписания, карточки и вступления
в команду. После привязки аккаунта выберите команду, отметьте несколько ролей и нажмите
«Отправить заявку». Повторное нажатие на роль снимает выбор. Принятие в команду требует
одобрения администратора на сайте. Новые приглашения содержат кнопки подтверждения
и отказа; старые команды `/accept_ID` и `/decline_ID` остаются совместимыми.
Регистрация аккаунта и привязка Telegram выполняются через сайт; бот не запрашивает
пароль, слова подтверждения и не показывает технический JSON.

Участники создают собственные аккаунты и вступают в команду через заявку. Ручное создание карточек без логина отключено; существующие карточки и назначения сохраняются.


### Назначения на событие

В расписании нажмите название события («Состав и назначения»). Администратор или
координатор выбирает роль и служителя, затем нажимает «Назначить на событие».
Состав можно заполнить даже у события без заранее созданных мест. В карточке также
можно заменить служителя или очистить назначение. Сервер проверяет права и соответствие
роли служению, сохраняет назначение и ставит уведомление участнику в очередь.
Кнопка выхода расположена в верхней панели и доступна на узких экранах.


### Доступность и запросы замены

Раздел «Доступность» показывает будущие назначения текущего пользователя во всех его
командах. Нажатие названия или «Открыть событие» открывает полный состав, репетицию,
песни и одежду, в том числе для событий другого месяца или другой своей команды.
Кнопки «Подтвердить» и «Запросить замену» сохраняют ответ в общем расписании.
При назначении привязанный Telegram-аккаунт получает такие же inline-кнопки.
Ответ разрешён только назначенному человеку; устаревшие кнопки после изменения
назначения отклоняются. Запрос замены доступен и после подтверждения: участник остаётся
назначенным со статусом «Запрошена замена», координаторы и админы этой команды получают
уведомление. Повторный запрос не создаёт дубликаты. Назначение другого человека сбрасывает
статус на ожидание ответа. Раздел обновляется при возвращении
во вкладку и каждые 30 секунд.

Telegram-уведомления показывают дату словами и местное время события (часовой пояс
серии, по умолчанию Europe/Saratov), включая старые задания, ещё находящиеся в очереди.
Текстовый сценарий регистрации больше не создаёт неизвестные роли; новые роли может
добавить администратор через справочник команды.


## Календарь и участие

В расписании доступны календарь месяца и таблица состава. Нажмите дату, затем событие,
чтобы открыть назначения, репетицию, песни и одежду. Статусы участия обновляются автоматически.
На телефоне основная навигация расположена внизу и подписана.
У обычного служителя в меню три раздела: «Расписание», «Доступность» и «Участники».
Кружок пользователя справа вверху открывает настройки аккаунта.

Админы и координаторы могут удалить событие из его карточки с подтверждением.
Удаляется только выбранная дата, остальные события серии сохраняются; связанные
назначения, история песен и задания уведомлений удаляются каскадно.

Настройки доставки уведомлений доступны всем в личной карточке и кнопкой в «Доступности»,
даже если уведомления ещё не подключены. Переключатель в событии задаёт личную подписку:
по умолчанию включён при наличии назначения и выключен для остальных событий.
Можно подписаться на другое событие своей команды. Отключение учитывается при подготовке
и доставке уведомлений в Telegram и Web Push. Запросы замены руководителям доставляются
независимо от их личной подписки. Напоминания приходят по установленным для события срокам;
доставка в браузер дополнительно требует разрешения на конкретном устройстве.
Миграция `0015_event_notifications` добавляет таблицу личных подписок; существующие
назначения автоматически используют включённые уведомления без заполнения таблицы.

Вкладка «Доступность» содержит личные назначения и ответы на них. В карточке события
роль, значок ответа и единственное поле выбора служителя собраны в одну строку.
Часы означают ожидание ответа, галочка — подтверждение; подсказка доступна по значку.
Кнопка «Вложения» в помощнике добавляет файлы расписаний.

Все участники служения видят все события месяца. Переключатель «Только с моим участием»
фильтрует календарь и таблицу по личным назначениям, включая ещё не подтверждённые;
по умолчанию выбран режим «Все события».

Одноразовая ссылка входа действует пять минут. Сессия после входа действует семь дней
с момента выдачи токена; срок задаётся `JWT_LIFETIME_MINUTES=10080` в `.env`.
Изменение настройки применяется при следующем входе, существующие токены не продлеваются.

Новые события прославления получают базовый состав из девяти мест: ведущий вокал,
два бэк-вокала, барабаны, бас, электрогитара, акустическая гитара, клавиши и звукорежиссёр.
Дополнительные места добавляются в карточке события; служителя можно выбрать позже.
Базовый состав применяется также к событиям, созданным из черновика помощника.

В «Участники → Виды собраний» координатор или администратор настраивает для каждой роли,
на каких событиях может служить человек: воскресные собрания, вечер хвалы и молитвы,
молитвы, общие лидерские и другие события. Пустой список разрешает все виды.
Ограничения проверяются сервером при назначениях, самостоятельной записи и применении
черновика помощника. Существующие несовместимые будущие назначения нужно изменить до
сохранения ограничения. Вид собрания выбирается при создании и доступен в карточке события.

Песни и одежду редактирует только назначенный на конкретное событие ведущий вокалист.
Изменения сохраняются с проверкой версии и уведомляют назначенных участников через
Telegram и Web Push. Неизменённый текст не создаёт повторных уведомлений.
При входе сайт предлагает подключить уведомления; разрешение браузера выдаёт сам пользователь.


## Архитектура Telegram-бота и журналы

Бот разделён на настройки, HTTP-клиенты, клавиатуры, обработчики и фоновые задачи.
Он не обращается к базе напрямую; правила доступа и назначения остаются в backend.
Подробнее: [bot_service/README.md](bot_service/README.md).

API, бот и Web Push worker выводят структурированные JSON-логи с корреляцией запросов,
результатами операций и безопасными сведениями об ошибках: [LOGGING.md](LOGGING.md).
